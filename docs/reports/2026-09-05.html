为AI编码代理打造的性能增强框架

Markdown 规则配置Claude CodeCodexOpencodeCursorAgent Prompt Engineering
该项目是一个面向 AI 编码代理（Agent Harness）的性能优化系统，旨在为 Claude Code、Codex、Opencode、Cursor 等主流 AI 编程工具提供统一的能力增强层。项目围绕五大核心维度构建：Skills（技能库）为代理提供可复用的专业能力模块；Instincts（直觉）赋予代理更符合工程实践的决策倾向；Memory（记忆）解决跨会话的上下文持久化问题；Security（安全）建立代码执行与数据处理的防护机制；Research-first Development（研究优先开发）则强调在动手编码前先进行充分的信息收集与方案验证。整体设计理念是把资深工程师的工作习惯抽象为可配置、可复用的规则与工具集，让 AI 代理不再仅仅是代码补全器，而是具备工程判断力的协作伙伴。项目采用工具无关的架构，通过适配层对接不同的 AI 编码平台，使得同一套优化策略可以跨生态复用。这对于长期使用 AI 编码工具的开发者而言，能够显著减少重复配置、提升代理输出质量、降低幻觉与安全风险，是当前 Agent Ops 领域一个具备实用价值的探索。
在 AI 编码代理泛滥但质量参差不齐的当下，该项目跳出单一工具的绑定，从工程方法论层面为代理建立统一的行为规范与能力底座，是 Agent Harness 优化方向上少见的系统性尝试，对追求 AI 编码稳定性与安全性的团队具有直接参考价值。

Forward Implementation First ⭐ 163

让 AI 编码代理专注交付而非记账

MarkdownYAML FrontmatterAgent Skills 约定Shell 安装脚本Claude Code / Codex 兼容
Forward Implementation First 是一个面向 Claude Code、Codex 等 AI 编码代理的 Skill 技能包，用于解决长流水线场景下代理陷入自我制造的行政性工作的问题。当代理面对哈希、锁文件、执行回执、认证标记、进度元数据等辅助记账信息时，容易将其误认为正确性证据，从而进入无休止的元数据修复循环，实际产出却毫无变化。该技能通过约 150 行 Markdown 规则，要求代理在每次动作前进行三选一分类：语义实现（构建生产者、消费者、适配器、Schema 等真实产物）、聚焦式验证（对变更依赖锥进行行为、Schema、计数、时间与内存等测量）、行政性记账（哈希、锁、回执、仪表盘等）。前两类照做，第三类除非用户明确要求或作为产品本身的一部分否则跳过，若其阻塞路径则直接删除依赖。技能同时确立了前向游标规则，明确只有输入变更、目标修订变更、输出畸形、运行反证、依赖锥要求等真实理由才可回放阶段，缺失或过期的元数据不构成回滚依据。在并行方面，技能不充当调度器，只保留发布唯一写者、消费前验证输出、按需拉取产出、禁止编造忙碌等不变量。它是模型无关、工具无关、领域无关的纯 Markdown 规则，遵循 Agent Skills 约定，可通过 install.sh 一键安装到多种代理的 Skill 目录。
这个仓库并不提供代码库，而是把一种被广泛观察到的 AI 代理失败模式——把自造的记账工作当作产品——提炼为一份可复制粘贴的 150 行规则。它在保留真实证据（测试、基准、输入身份、产品级校验和）与剔除伪装成正确性的元数据之间划出了清晰边界，还前瞻性地把并行部分从调度器收敛为不变量，避免与真实运行时冲突。对于任何跑长流水线、ETL、代码迁移或多代理协作的团队，这是一份低成本、高信噪比的工程实践总结，值得作为 Agent Skill 生态中的参考样本。

useAgent ⭐ 284

开源 AI 同事，交付成品而非答案

BunTypeScriptPostgres 16 + pgvectorDaytona / CubeSandboxnoVNCSlack AppGitHub AppTerraform (Hetzner 参考)OpenRouter
useAgent 是一款开源的团队级 AI 协作平台，把 Claude Code、Codex、OpenCode 等 AI 编码代理封装成拥有独立云端计算机的「AI 同事」。与传统只返回对话答案的助手不同，它把代理放进隔离的 Linux 沙箱工作站，配备终端、代码仓库、浏览器与可视化桌面（noVNC，支持 MP4 录制），最终交付可编辑的成品：网站、幻灯片、表格、研究报告、经过测试的 Pull Request 以及 DOCX/XLSX/PPTX/PDF 原生文档。核心设计有三条：一是引擎即插件，所有代理通过统一的规范化事件契约接入，可自由替换；二是每次运行都是事件溯源日志，以 Postgres 作为唯一真实源，运行可在后端重启后恢复、可精确回放、可事后审计；三是凭据永不进入沙箱，知识库、记忆、技能、GitHub、Web 搜索、桌面操控等都通过可信网关以类型化工具形式暴露，密钥仅存于控制面。产品原生支持 Slack（提及触发、线程回复、审批卡）、GitHub App、以及 Gmail、Linear、Notion、HubSpot 等 OAuth 连接器；支持 SKILL.md 技能导入、组织级知识检索与团队记忆学习通道。危险操作会在 Web 或 Slack 中弹出人工审批卡，凭一次性能力恢复执行。项目基于 Bun 运行时与 Postgres 16+（pgvector），可自托管到任意云或裸机，沙箱层可选托管的 Daytona 或自托管的 CubeSandbox，遵循 AGPL-3.0 协议。
useAgent 直面当前 AI 编码代理「只给答案不交付成品」和「凭据暴露给沙箱」两大痛点，用事件溯源 + 可信网关 + 引擎适配器的组合，把 Claude Code、Codex 等命令行代理产品化为可审批、可回放、可自托管的团队协作系统，并原生打通 Slack 与 GitHub 工作流，是少见把「AI 同事」这一叙事落到工程实处的开源方案。

notion-doc ⭐ 76

让 AI 生成 Notion 风格文档

HTML/CSSPython 3 (标准库)Claude Code Plugin/SkillPrism.js (代码高亮)GitHub ActionsHeadless Browser
notion-doc 是一个面向 Claude Code 的 Agent Skill 插件，专门解决 AI 生成文档普遍呈现紫色渐变、堆砌 emoji、卡片阴影泛滥等审美问题。它不干预内容与大纲，只统一视觉呈现，将 AI 输出规范为 Notion 风格。项目核心是一个 template.html，定义了 720px 内容宽度、Notion 亮/暗色调色板 CSS 变量，并提供了完整的 Notion 常见块：emoji 页面图标、面包屑、目录、5 色 callout、表格、双栏布局、按钮、toggle、清单、书签卡、Prism 语法高亮代码块、韩语友好断行以及打印/PDF 布局。配套 lint.py 使用纯 Python 标准库校验生成文档是否偏离模板（禁止内联 style、随意新增类名或 CSS），并通过 PostToolUse Hook 在写入 HTML 后自动提示。GitHub Actions 每周同步 Notion 官方 token 与 block 类型基线，确保风格不漂移。除 Claude Code 外，也支持 Codex、Cursor、Gemini CLI 等任意可读取指令文件的 Agent。
