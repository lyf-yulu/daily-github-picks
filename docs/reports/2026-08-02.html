codex-deepseek-vision ⭐ 119

让纯文本 DeepSeek 在 Codex 中无痛看图

Python 3.11+OpenAI-compatible Chat Completions APISSE 流式转发本地 HTTP 代理DeepSeekCodex CLI
codex-deepseek-vision 是一个本地代理方案，专为已经在 Codex 中接入 DeepSeek 等纯文本大模型的用户设计。它解决的核心痛点是：纯文本模型没有多模态能力，一旦用户贴图或模型调用 Codex 内置的 view_image 工具就会被系统拦截报错，导致体验断裂。该项目通过在 127.0.0.1:19100 起一个本地代理，拦截 Codex 与 DeepSeek 上游之间的请求，当检测到消息中包含图片（贴图形式的 message.content 或工具调用返回的 function_call_output.output）时，自动调用一个 OpenAI 兼容的多模态视觉 API 将图片转成文字描述，再把描述替换回请求中转发给 DeepSeek，从而让纯文本模型也能顺畅处理图片问答、截图分析、GUI 操作等场景。项目实现了多图并行调用、按 sha256 缓存图片描述以避免重复请求、以及仅在 catalog 声明为 text-only 时才补充 image 支持等细节优化。除了代理主体，仓库还附带两个可选 CLI：glance 用于对单张图片直接提问或做 OCR，ground 用于用自然语言在原图中定位目标并输出像素级边界框。DeepSeek 的认证由 Codex 原样透传，代理只需配置 VISION_API_KEY、VISION_BASE_URL、VISION_MODEL 三个环境变量。
在多模态模型日益普及的当下，仍有大量用户因成本、私有化或已有工作流选择 DeepSeek 这类纯文本模型，本项目用极轻量的代理层弥合了纯文本模型与 Codex 内置视觉工具之间的鸿沟，无需引入额外的 MCP、Skills 或 CLI，就能让 view_image、贴图、截图分析、Computer Use GUI 操作等场景开箱可用。并发 + 缓存的工程细节表明作者在真实会话中做过打磨，思路也可复用到其他纯文本模型接入多模态工具链的场景，具备较强的参考价值。

micro-vLLM ⭐ 111

教学向的轻量级 vLLM 推理引擎

PythonPyTorchCUDATritonHugging Face TransformersSafetensors
micro-vLLM 是一个面向学习与实验的轻量级 LLM 推理引擎，定位介于极简的 nano-vllm 与生产级 vLLM 之间。项目保留了 vLLM V1 的核心架构分层，包括 Engine、Scheduler、KVCacheManager、Executor、Worker、ModelRunner、Model 与 Attention Backend 之间清晰的职责边界，同时主动收敛功能范围，专注于自回归 decoder-only（Causal LM）模型的推理流程，让读者能够在规模适中的代码库里理解 vLLM 的核心抽象。在能力上，它实现了同步离线批量生成、continuous batching 与 token-budget 调度、Paged KV Cache、prefix cache 与请求抢占，并提供 reference、PyTorch SDPA 和 Triton 三种 paged attention 后端，支持 Llama、Mistral 和 Qwen3 等 Causal LM 模型。项目复用 Hugging Face 生态加载模型配置、Tokenizer 与 Safetensors 权重，并针对调度与 KV Cache 提供结构化 trace，测试上区分了 CPU 单元测试与 GPU/真实模型集成测试。项目原则明确按语义正确、教学清晰、抽象稳定、可测量的性能优化、功能覆盖的顺序取舍，当功能扩展与核心链路清晰冲突时优先保证后者，因而非常适合作为深入理解 vLLM 架构的学习底座。
LLM 推理系统的学习资料要么过于简化偏离真实工程结构，要么直接面对 vLLM 庞大的代码库门槛过高。micro-vLLM 以贴近 vLLM V1 的分层实现了一条更短的学习路径，把调度、Paged KV Cache、prefix cache、抢占和多种 attention 后端等核心机制拆解到可读的规模，对研究推理引擎、想动手扩展调度或缓存策略的开发者与学习者具有较高参考价值。

Bindwidth 本地大模型选型计算器 ⭐ 55

私有化本地 AI 部署选型与成本测算工具

JavaScriptReact (CDN)htm (CDN)纯 HTML/CSS 无框架JSON 数据目录Node.js 测试GitHub Pages
Bindwidth 是一款面向私有化本地大模型部署的、基于证据的选型与总拥有成本（TCO）计算器。它围绕三大真正决定单模型驻留下限的约束（KV 缓存内存、Prefill/Decode 合并服务容量、运行时会话上限）进行显式评估，帮助用户识别真正的瓶颈（bind），避免为非绑定约束买单。工具区分交互式用户与自主 Agent 两种结构性不同的负载，基于薪资、并发峰值、模型架构（总参/激活参/精度/KV 每 token/推测解码/预填解码比）等参数推算所需机器数，并透明对比自有硬件、主权云租赁与企业订阅三条路径，同时标注能力与服务差异。项目为纯前端应用，无构建、无服务器、无遥测，所有计算在浏览器内完成；模型、硬件、基准等数据以 JSON 目录分离，贡献者只需修改 JSON 即可扩展。引擎为纯函数，配套多组测试固定关键算术结果，并可导出 Markdown 决策记录与 JSON 场景。

Ratchet ⭐ 408

为编码 Agent 加装的复杂度棘轮

Node.js 20+Claude Code HooksJavaScriptGitWindows 原生 UI (ratchetui.exe)
Ratchet 是一款面向 AI 编码 Agent（如 Claude Code）的复杂度守护工具。作者提出一个核心观察：向模型注入‘偏好标准库、不加依赖、保持小 diff’之类的极简规则只是‘开环’提示，长会话中模型必然漂移，却没有机制去验证它是否真的遵守。Ratchet 通过 Claude 的 PostToolUse 钩子在 Agent 每次 Edit/MultiEdit/Write 后立即读取改动，运行一组检测器并把发现回注到同一会话，让模型在还在工作时就看到自己的越界行为。检测项涵盖新增依赖（dep）、重复符号（exists）、手写标准库替代（stdlib）、平台已具备的能力（native）、只做转发的包装函数（wrapper）、单实现的抽象（yagni）、自造邮箱正则（validation）以及新文件、新依赖、净新增行数的预算（budget）。发现按 certain/likely/heuristic 三级分级，只有 certain 会在 strict 模式下阻断编辑。工具提供 advise/guard/strict/off 四档模式，可通过 /ratchet 指令或环境变量切换。同时以 .ratchet/mark.json 记录被接受的复杂度基线、以 ledger.jsonl 追加每次会话的净变化，用 ratchet report 输出真实趋势而非估算百分比，并支持 ratchet-ignore 注释与 baseline 对存量债务进行豁免。名字取意‘棘轮’：复杂度只能下降或持平，除非有人显式抬高基线并写下原因。
它触及 AI Coding Agent 工程化的一个真痛点：系统提示无法保证规则被遵守。Ratchet 用最朴素的思路——外部检测器 + 会话内反馈回路——把‘写规则’变成‘验规则’，并用可审计的 ledger 取代常见的‘AI 帮你节省了 X%’式营销数据，思路值得同类 Agent 工具生态借鉴。
