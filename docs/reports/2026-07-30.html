Agent Harness 性能优化系统 ⭐ 857 (+857 today)

为 AI 编程代理提供技能与记忆增强的性能优化框架

Claude CodeOpenAI CodexOpenCodeCursorPrompt / Skill 模板工程Agent Memory 机制
该项目是一个面向 AI 编程代理（Agent）的性能优化系统，旨在通过统一的 harness（承载框架）为 Claude Code、Codex、OpenCode、Cursor 等主流 AI 编码工具提供能力增强层。项目的核心理念是围绕五大支柱构建代理的工作方式：Skills（可复用技能库）、Instincts（内建直觉与最佳实践）、Memory（跨会话记忆）、Security（安全护栏）以及 Research-first Development（研究优先的开发范式），意在解决当前 AI 编程助手在长任务中容易遗忘上下文、缺乏领域直觉、安全边界模糊以及先编码后思考等痛点。通过在代理运行时注入结构化的技能模板、行为准则和检索机制，让不同厂商的代理表现出更一致、更可靠、更符合工程规范的能力。项目采用工具无关（tool-agnostic）设计，可以横向覆盖多种代理运行环境，成为开发者自定义 AI 工作流的基础设施层。由于 README 内容极为精简，具体实现细节、配置格式和 CLI 接口尚需查阅仓库源码进一步确认，但从定位来看，它面向的是希望统一管理多套 AI 编程代理配置、追求高质量代码产出的进阶开发者与团队。
在 AI 编码助手百花齐放的当下，各家工具能力割裂、上下文遗忘、缺乏安全约束是普遍痛点。该项目试图建立一个跨代理的统一优化层，把工程实践中沉淀的直觉、记忆与安全规范抽象成可复用组件，代表了从「用 AI 写代码」到「治理 AI 写代码」的思路升级，对希望在团队内规模化落地 AI 编程的开发者具有参考价值。

agentacct ⭐ 528

本地优先的编码 Agent 用量与工作追踪仪表盘

Python 3.11+pipx / uv (分发)MCP (Model Context Protocol)Claude Code HooksOTLP (可选本地遥测接收)本地文件存储 (~/.local/state/agentacct)本地 HTTP Dashboard (127.0.0.1:8765)
agentacct 是一款面向 Claude Code、Codex、OpenCode、Cursor 等编码 Agent 的本地优先「Agent 工作情报」工具。它读取这些客户端本地已经生成的会话日志，将 Token 用量与 Agent 在工作中通过 MCP 记录的任务步骤、机器检查（如测试运行）关联起来，并在本机 127.0.0.1 上的仪表盘中呈现任务、工具使用、文件改动、测试结果、耗时与预估成本。项目强调隐私与诚实：所有状态以纯本地文件形式保存，不做任何远程遥测、账号或云同步，也从不请求或存储 Provider API Key；Token 数据来自客户端自身文件并明确标注为 client_reported，成本仅是本地价目表的估算而非发票。它以 pipx/uv 安装、通过 agentacct onboard 一次性完成全局或按项目安装，自动检测本地 Agent 日志并启动仪表盘。归因方面，每一条用量与工作的关联都会打上 exact/high/medium/low 置信度标签，宁可显示缺口也不做臆测；Claude Code 通过 Hook Bridge 捕获真实 session/transcript id，Codex 从会话日志中提取，其他客户端按能力矩阵有明确范围声明。项目采用 Python 3.11+，支持 macOS 与 Linux（Windows 需 WSL），当前处于早期 alpha，MIT 协议开源。
在 AI 编码 Agent 成本失控、用量口径混乱的当下，agentacct 用「本地优先 + 诚实标签」的姿态填补了一个真实缺口：它既不假装能给你一张发票，也不用云端 SaaS 换取观测能力，而是直接消费 Claude Code / Codex 已经写到本地的会话日志，并通过 MCP 让 Agent 自己记录工作步骤与机器检查，最后以置信度标签把「Agent 说做了什么」与「机器验证做了什么」分开呈现。这种对可验证性的克制，加上零 API Key、零遥测、零账号的隐私姿态，在 Agent 可观测性赛道里是一种少见且工程化程度较高的路径。

开放图像提示词档案库 ⭐ 139

本地优先的可溯源视觉提示词库

Node.js 20+/22+Python 3 (uv)SQLite (FTS 只读模式)前端 Vite (端口 5173)DockerGitHub Releases 数据分发Agent Skills (npx skills)
Open Image Prompts 是一个开放、本地优先的视觉提示词档案库项目，围绕可溯源的「提示词-图像」引用关系构建，并提供两个可安装的 Agent Skills。项目通过 `img-gen-taste` 将粗略创作意图转化为清晰艺术方向，通过 `img-gen-prompts` 检索带图像佐证的提示词参考并打开本地对比画廊。公开数据集包含 14,028 条源提示词、24,305 张图像、28,056 条双语翻译、163,135 条 v2 有效标签，以及 185 个视觉标签构成的封闭分类体系。为保持仓库轻量，项目不使用 Git LFS，而是通过 GitHub Releases 分发数据资产：`scripts/fetch_dataset.py` 会下载约 80MB 的 SQLite 压缩包和可选的月度图像包（总计约 4.3GB），并进行 sha256 校验。用户可通过 `start.sh` 或 `start.bat` 一键启动，脚本会自动安装 uv、创建 Python 环境、拉取数据集、安装前端依赖并同时启动 API 与前端服务。项目也支持 Docker 化部署，API 默认仅绑定 127.0.0.1，SQLite 以只读不可变模式打开，安全边界清晰。公开数据集严格限定于运行时数据，不含标注候选、模型配置、评估表和历史标签，另有 72 条中英双语回归基准用于检索质量测试。
在 AIGC 提示词大量散落于社区截图与聊天记录的当下，该项目提供了一个稀有的开放、可溯源、本地优先的提示词-图像语料库，且以 Agent Skills 形式对接编码智能体，具备工程规范（数据/代码分离、只读 SQLite、回归基准、公开数据边界声明），为提示词工程和视觉检索研究提供了可复现的基座。

optim-plans ⭐ 115

人机协同的Agent计划与执行双环插件

Python 3.11+Claude SkillCodex SkillGit worktreeMarkdownGitHub CLI (gh)GitHub Actions CI
optim-plans 是一个面向 Claude 和 Codex 的人机协同（human-in-the-loop）规划插件，专为提升 Agentic Coding（智能体编程）的可靠性而设计。它通过引入两个闭环解决 Agent 常见的两类问题：一是「规划-精炼环」（Planning-refining ring），将模糊需求转化为可评审的 Markdown 计划，通过 Reviewer 或 Criticizer 反复迭代，将每个决策的疑问在写代码前解决；二是「执行-验证环」（Executing-validating ring），要求所有执行必须基于不可变的 manifest 与显式的人工批准才能启动，在受控的 Git worktree 与专用分支中串行推进任务，插入只读 validator 进行 safe-audit，并强制通过控制器验证与 Git 审计后才 checkpoint，最终干净通过则自动 fast-forward 集成回目标分支。项目产出物分为两类：一类是位于 docs/optim-plans/ 下的公开 Markdown 计划文档（PLAN_v1、评审意见、PLAN_v2、执行摘要），另一类是位于 .git/optim-plans/ 下可回放的机器状态（run.json、events.jsonl、controller.lock 等）。此外，$optim-plans:review-and-plan 子命令能先对仓库做全面审视，从文档、效率成本、功能完备度、用户体验、安全可恢复性五个维度产出排序改进建议，并强制引用 GitHub 开源项目作为佐证来源。整个方案以 Python 3.11+ 实现，附带 CI 与受测的 controller 原语，让 Agent 工作流兼具可审查性与安全性。
在 Agent 编程工具普遍追求「更自动」的趋势下，optim-plans 反其道而行，把「人类审批」和「显式门禁」作为一等公民，用 manifest 哈希、run worktree、controller.lock 等工程化手段把 Agent 的不确定性关进笼子。它同时兼容 Claude Skill 与 Codex Skill 两大生态，产出物是纯 Markdown 便于评审，机器状态可回放便于事后审计，非常适合关心 Agent 安全性、可复现性与团队协作规范的开发者参考借鉴。
