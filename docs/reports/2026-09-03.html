为AI写作去味的Agent Skill

Agent Skills 规范Markdown（SKILL.md）Skills CLI（npx skills）Claude Code PluginCodex PluginGrok Build PluginAntigravity Plugin（plugin.json）
sepia 是一款可移植的 Agent Skill 写作技能包，专注于消除 AI 生成文本的特征痕迹（De-AI writing）。与传统仅在词汇和句式层面做替换的“人性化改写器”不同，sepia 依据 StoryScope（arXiv:2604.03136，基于 61,608 篇故事与 5 个前沿 LLM 的实证研究）等 11 篇研究成果，从叙事结构层入手修复 AI 小说的架构性破绽：主题过度点明、单线因果闭合、情绪仅以身体感知呈现、缺乏现实指涉、线性时间与成长式结局等。项目提供 write、review、refactor、recreate 四种操作，分别对应新写、仅诊断、最小改动、彻底重写。对小说采用“叙事架构 → 话语流 → 表层文体”的三遍修订协议，并针对 Claude、GPT、Gemini、DeepSeek、Kimi 等模型内置指纹识别；对发行说明、PR 回复、事故复盘、工单、技术文章等专业文本则匹配各自场景规则。基于 Agent Skills 标准，通过 Skills CLI 可一键安装至 77+ 兼容 Agent，并为 Claude Code、Codex、Grok Build、Antigravity 提供原生插件封装。自 v0.4.0 起还支持叠加外部“声音/风格”技能。
多数“AI 去味”工具停留在改词换句的浅层，sepia 是少见的把学术论文（StoryScope 等 11 篇研究）的量化结论工程化为可复用 Agent Skill 的项目，并覆盖叙事架构层这一真正暴露 AI 的维度。同时以“一份技能、跨 77+ 代理”的形态解决了 Agent 生态碎片化问题，并提出“对齐人类分布而非反转 AI 分布”的方法论，兼具研究深度与工程可用性。

Agent Harness 性能优化系统 ⭐ 516 (+516 today)

面向 AI 编码代理的能力增强框架

AI AgentPrompt EngineeringClaude CodeCodexCursorOpencode
该项目是一个面向 AI 编码代理（Agent Harness）的性能优化系统，旨在为 Claude Code、Codex、Opencode、Cursor 等主流 AI 编程助手提供统一的能力增强层。项目围绕五大核心维度构建：Skills（技能）用于封装可复用的专业能力模块，Instincts（直觉）通过预设启发式规则让代理形成更可靠的判断本能，Memory（记忆）解决长期上下文与知识沉淀问题，Security（安全）为代理执行环境提供护栏与权限控制，Research-first Development（研究先行开发）则倡导代理在动手编码前先进行充分的信息检索与方案调研，从而减少幻觉与返工。整体设计理念是将原本零散、经验化的提示词技巧与工作流规范，抽象为可组合、可复用、可跨平台的标准化模块，使不同厂商的 AI 编程代理都能在同一套框架下获得更稳定的输出质量与更强的工程化能力。项目定位于生态层的粘合剂，而非某个特定 IDE 或模型的专属插件，因此对多代理协作、企业级落地以及个人开发者提升日常编码效率都具有参考价值。由于当前仓库 README 信息较为精炼，具体实现细节需结合后续文档与源码进一步了解。
在 AI 编码工具百花齐放的当下，各家代理的能力边界与工作流规范高度碎片化。该项目尝试用一套通用的能力抽象（技能、直觉、记忆、安全、研究先行）统一多家代理的性能优化范式，属于生态层的基础设施探索，对希望在企业内推行 AI 辅助开发标准的团队具有较高参考价值。

Forward Implementation First ⭐ 161

阻止编码智能体沉迷自制簿记的技能规则

Markdown (SKILL.md)YAML frontmatterBash (install.sh)Agent Skills 规范Claude Code / Codex 兼容
Forward Implementation First 是一个面向编码智能体（Claude Code、Codex 等）的 Agent Skill，用一份约 150 行的 Markdown 文件解决长流水线场景下智能体被自造簿记拖住的顽疾。项目观察到，当流水线包含哈希、锁文件、receipts、认证标记、进度元数据等辅助信息时，模型容易把这些行政性产物误当成产品本身，一旦哈希失配就大范围回滚、拒绝手工推进，最终耗费数小时修复与结果无关的标记。该技能要求智能体在每次动作前进行三分类：语义实现、聚焦验证、行政簿记；只做前两类，第三类除非用户明确要求或属于产品交付内容否则跳过，并在阻塞路径时直接删除多余门槛。项目同时提出「forward cursor 规则」，明确只有输入含义变化、目标版本变化、输出畸形或被实测推翻等真实原因才允许回放阶段。对并行执行，它只保留调度无关的不变量（单一写入者、消费前校验、不等待空闲、不造无用功），把 worker 数量、波次等调度策略交还给运行时。技术上是模型无关、工具无关的纯 Markdown 规则，通过 install.sh 拷贝到 Claude Code、Codex 或共享 ~/.agents/skills 目录即可生效。
这是一个从工程实践中提炼出的高信噪比 Agent Skill：它不追求「让模型更快」，而是精确定义了智能体在长流水线中最常见、最昂贵的失败模式，并用极简规则约束模型行为，同时明确保留了产品自带的完整性校验和真实证据链，避免落入「无脑跳过检查」的另一端陷阱。对使用 Claude Code、Codex 做代码迁移、ETL、构建发布等长任务的团队具有直接落地价值。

useAgent ⭐ 274

开源 AI 同事，交付成品而非答案

TypeScriptBunPostgres 16 + pgvectorDaytona / CubeSandboxnoVNCSlack APIGitHub AppTerraform (Hetzner 参考)AGPL-3.0
useAgent 是一个面向团队的开源 AI 协作平台，把 Claude Code、Codex、OpenCode 等既有 AI 编码代理封装成拥有独立云端计算机、公司工具和上下文的“数字同事”。它不只返回答案，而是直接交付可用成果，包括网站、幻灯片、电子表格、研究报告以及经过测试的 Pull Request。核心设计围绕三点：引擎可插拔，Claude Code、Codex、OpenCode、Pi 都通过统一的引擎适配器讲同一套事件契约，切换引擎不影响会话、产物和记忆；每次运行都是事件溯源日志，以 Postgres 作为唯一事实源，支持后端重启后精确回放和事后审查；凭据永不进入沙箱，代理的“计算机”被隔离，所有集成都通过受信网关以类型化工具形式调用，密钥仅存于控制面。功能上支持 Daytona 与 CubeSandbox 两套隔离 Linux 工作站（含终端、仓库、浏览器、noVNC 桌面与 MP4 录像），提供人机协同的审批卡、来自 GitHub 的 SKILL.md 技能导入、组织级知识库与团队记忆检索、Slack 原生 mention-to-run，以及 DOCX/XLSX/PPTX/PDF 原生产物编辑。整体采用 Bun 运行时，Postgres 16+ 搭配 pgvector 向量扩展，可自托管于任意 Linux 主机或云平台。
在 AI 编码代理趋于同质化的当下，useAgent 用“引擎即插件 + 事件日志 + 受信网关”的架构解决了企业级落地的三大痛点：多模型统一编排、运行可恢复可审计、凭据零泄漏。它把 Claude Code、Codex 等订阅制代理升级为可交付成品的团队同事，并提供 AGPL 完整自托管路径，是想在自有基础设施上运行多 Agent 协作的团队的稀缺样本。
