SkillForge 定位为面向 AI Coding Agent（Claude Code、Cursor、Codex、Gemini CLI 等）的『技能版 npm』，坚持本地优先、模型无关、MCP 原生三大理念。它将 Agent 能力抽象为可校验、可组合、可通过 MCP 暴露的独立技能单元，让 Agent 像安装包一样复用能力，并通过白名单沙箱（allow.read_paths / allow.write_paths / allow.net_hosts）约束读写与网络范围。每个技能带有结构化清单 skill.yml、执行入口 SKILL.md、评测基线 eval.md 与可选脚本资源。该仓库为公开『内容仓』，仅保留技能源文件、文档与镜像白名单，Web UI 源码、Rust CLI 与 registry 实现位于私有 Core 仓，通过 GitHub Actions 跨仓推送到 gh-pages 分支，由 skillforge.c8.fit 对外服务。项目提供已编译的 Rust CLI 四平台二进制（macOS arm64/amd64、Linux arm64/amd64）与 Next 14 SSG 静态站点，并构建了完整的 Ed25519 三层可信签名链：可信根签发 manifest 清单，manifest 清单登记每个归档的 sha256 与 BLAKE2b-512 哈希，归档本体再由 .sfminisig 单独签名，配合可复现构建（SOURCE_DATE_EPOCH + 规范化 tar 参数）确保同一 commit 产物哈希完全一致，任何篡改在验签阶段即被拒绝。
在 AI Agent 工具生态里，大多数『技能』方案仍停留在提示词模板层面，缺少版本管理、权限沙箱与可信分发机制。SkillForge 用类似 npm 的思路把技能变成一等公民：既有 skill.yml 清单和白名单沙箱这样的『软工程』约束，也有 minisign 风格签名 + 可复现构建这样的『供应链安全』基建，同时通过 MCP 原生对接主流 Agent 客户端。这种把包管理、安全签名与 Agent 运行时融合的做法，对正在寻找可复用能力标准的 AI 编码工具链具有参考价值。

AI 短剧制作的 Agent skill 集合

Node.js (>=18)Claude CodeCodex CLIShell 脚本Mermaid/Markdown 文档
shuohao-skills 是一个面向 AI 短剧制作场景的 Agent skill 集合，目标是把一本小说转化为可以直接开拍的制作素材，覆盖拆角色、出设定图和排大纲三个核心环节。项目当前提供两个 skill：novel-characters 负责把小说拆解成角色设定集，输出人物画像、形象提示词、音色提示词以及角色设定图，报告语言和出图风格均可配置；novel-outline 则将小说改编成短剧大纲五件套，包括改编说明、人物表、爽点表、分集梗概和资产清单，并内置 13 道质量门进行脚本级检查，同时支持对已有大纲的体检模式。工程上项目遵循一套严格的仓库约定：每个 skill 自包含在独立目录中，必须包含给 Agent 读的 SKILL.md 工作流说明和一份不调用模型的 selftest.mjs 自测脚本，脚本仅依赖 Node 标准库、零 npm 依赖。安装方面通过 install.sh 自动识别本机的 Claude Code 或 codex 环境并做软链接，git pull 后即时生效，也支持指定 skill、指定 CLI 及卸载。运行不需要 API key，直接消耗当前会话额度；出图能力依赖 codex CLI 内置的 imagegen，可选启用。
在 Agent skill 生态里少见的垂直行业实践：把 AI 短剧这一具体工作流拆成可复用、可自测、跨 CLI 的 skill 模块，并用确定性脚本保证产出质量，为其他领域构建 Agent skill 提供了可参考的工程模板。

长时程智能体执行框架 LongHorizon-Harness ⭐ 552

让 AI 智能体持续数十小时完成复杂计算机任务

Python ≥ 3.10Claude CodeCodex CLIAgentAdapter 插件协议Environment 可插拔执行环境协议WeaveBench / OSWorld 2.0 / Terminal-Bench 2.1 评测体系
LongHorizon-Harness 是由高德（AMAP-ML）团队开源的长时程计算机使用（computer-use）执行框架，目标是在真实桌面与命令行环境中，让 AI 智能体像人类一样连续操作数十小时，稳定推进复杂任务直至完成。它并不训练新模型，而是作为一层执行、状态管理与结果校验系统，运行在 Claude Code、Codex CLI 等现有智能体之上。框架核心采用三角色分离设计：Manager 负责维护原始目标、已验证进度与下一步计划；Executor 每轮以全新上下文（fresh context）聚焦一个明确子任务，避免上下文漂移；Auditor 则独立检查文件、接口、日志与测试，只有通过独立验证的结果才会写入持久任务状态，从而实现可恢复、可审计的进度积累。框架同时支持 GUI 和 CLI 混合工作流，任务可在浏览器、终端、桌面软件和 3D 工具之间切换，覆盖前端开发、数据分析、运维调试、设计出图、文档演示、空间推理、游戏交互等场景。通过轻量的 AgentAdapter，Manager / Executor / Auditor 可分别接入不同模型和后端，兼容 Claude、GPT、Qwen 等，实现质量、速度与成本的平衡。项目已在 WeaveBench、OSWorld 2.0、Terminal-Bench 2.1 等基准上进行大规模评测，并登顶 Hugging Face Daily Papers 周榜。
长时程智能体是当前 AI Agent 领域最难啃的硬骨头，业界普遍卡在上下文漂移、进度不可验证、失败后无法续跑三大痛点上。LongHorizon-Harness 用一套工程化的三角色 + 独立审计 + 持久状态方案给出了可落地的解法，且不绑定模型、可直接叠加在 Claude Code 与 Codex 上，几乎没有迁移成本。项目在 OSWorld 2.0、Terminal-Bench 2.1 等主流基准做了成规模评测，并登顶 HF Daily Papers 周榜，对研究者和 Agent 应用开发者都有直接参考价值。

diri ⭐ 236

macOS 原生的编码代理并行编排器

RustGPUI (Zed)Swift 6PTY / 无头终端模拟器MCP (Model Context Protocol)tmux + ssh (远程节点)Homebrew Cask 分发
diri 是一款面向 macOS 的原生编码代理（coding agent）编排工具，让开发者能够同时运行 Claude Code、Codex、Cursor、Gemini 以及普通 shell 会话，并在多个 git worktree 或远程主机（通过 ssh+tmux）之间并行调度。它的核心价值在于把多代理协作的复杂度收敛到一个可信的侧边栏视图中：diri 会解析每个代理在终端上实际渲染的画面，实时判断会话处于「工作中 / 等待用户 / 已完成」三种状态，用户无需逐个终端切换查看。项目采用双进程架构，桌面端 diri 由 Rust + GPUI（Zed 团队的 GPU 加速 UI 框架）构建，负责窗口、侧边栏、终端渲染和命令面板；后台常驻的 Swift 守护进程 dirijord 持有 PTY 与子进程，维护按偏移量寻址的输出日志、无头终端模拟器、会话注册表和控制套接字，实现类似 tmux 的持久化——即使关闭应用或重启守护进程，会话依然存活并可回放。此外，diri 通过内置 MCP 服务器让代理之间可以互相编排：一个代理可以派生、监控并回应另一个代理。新增代理支持无需写代码，只需在 manifests 目录添加一个描述启动、恢复、按键映射与屏幕状态识别规则的 JSON 文件。项目同时在推进一个 Rust 版引擎（diri-engine），为未来跨平台到 Linux 和 Windows 铺路。
在 Claude Code、Codex、Cursor 等 CLI 型编码代理激增的当下，如何同时驾驭多个代理成为真实痛点。diri 用原生 macOS 应用而非 Electron 包壳的方式，把「多代理并行 + 状态可视 + 会话持久 + 代理互相编排」这四件事组合成一个完整工作流，且技术选型颇具野心——Rust + GPUI 桌面端搭配 Swift 守护进程，还在推进 Rust 引擎以跨平台。对于关注 AI 编码工具链、终端多路复用与原生桌面工程实践的开发者，都是一个具备工程深度的参考样本。
