基于叙事架构的去AI化写作技能

Agent Skills 标准Markdown（SKILL.md 规范）Skills CLI原生插件（Claude Code、Codex、Grok Build、Antigravity）
sepia 是一个便携式 Agent Skill，专注于从叙事架构层面修复 AI 生成文本的机器痕迹，而非仅在词汇和句式层面修饰。基于 StoryScope 研究（arXiv:2604.03136，分析了 61,608 篇故事），该研究证明仅使用叙事结构特征即可以 93.2% 的 F1 值检测 AI 小说，而表层风格编辑几乎无效。sepia 针对虚构写作采用三层修复策略：叙事架构层（停止解释主题、松散因果链、后置揭示、混合情感模式）、话语流层（打破段落-问题模板、修复中段疲软）、表层风格层（消除陈词滥调和句式模板）。对于专业文档（发布说明、PR 回复、事后报告、工单、技术文章），则根据文档类型匹配场景规则。项目提供四种操作模式：write（创建）、review（诊断）、refactor（最小编辑）、recreate（完全重写）。支持 77+ 种 AI 代理（通过 Skills CLI），并为 Claude Code、Codex、Grok Build、Antigravity 提供原生插件。采用单一规范的 SKILL.md 文件，无需针对不同平台维护分支。自 v0.4.0 起实验性支持与声音/风格技能组合，允许在架构决策之上叠加品牌语调或个性化风格。
这是首个将学术研究（StoryScope）直接转化为实用工具的去 AI 化写作方案，突破了传统人性化工具仅修饰表层的局限，从叙事结构根源解决 AI 写作的可检测性问题。其跨平台便携性设计和针对专业文档的场景化规则，使其既适用于创意写作，也适用于工程团队的日常协作文档优化。

Forward Implementation First ⭐ 161

防止 AI 编码代理陷入自创的事务性工作

Markdown（技能定义格式）YAML FrontmatterAgent Skills 约定模型无关（适用 Claude Code、Codex 等）
Forward Implementation First 是一个面向 AI 编码代理（如 Claude Code、Codex）的技能模块，旨在解决长时间运行的代理流水线中常见的「行政化陷阱」问题。当代理在多阶段流水线中工作时，容易将内容哈希、锁文件、执行凭证、进度元数据等簿记工作误认为产品本身，从而陷入无休止地修复和验证这些中间产物的循环，而非推进真正的功能实现。该技能通过约 150 行 Markdown 定义了一套分类规则：将每个行动归类为语义实现、聚焦验证或行政簿记三类，并明确要求代理优先执行前两类，跳过第三类（除非用户明确要求或该产物属于产品本身）。核心原则是「前向游标规则」：仅在输入语义变更、输出损坏、依赖锥要求等真实原因下才重放阶段，而非因元数据过期而回滚。技能保留了对产品完整性的严格验证（如用户可见的校验和、格式签名），但剔除了仅用于证明某阶段「已运行」的无效凭证。同时覆盖并行工作的不变量规则：单写者拥有发布权、输出验证先于消费、前向推进不等待所有工作线程。该技能与模型、工具、领域无关，适用于分阶段数据流水线、大规模代码迁移、构建发布管道等场景。
这是首个系统化解决 AI 代理「行政化陷阱」的技能模块，直击长时间运行流水线中代理将簿记工作误认为产品的核心痛点。通过明确的三分类决策和前向游标规则，使代理能够区分真实验证与无效凭证，避免在哈希修复等无意义工作上浪费大量 token 和时间。该技能仅 150 行，轻量且模型无关，可即插即用到任何支持 Agent Skills 约定的代理中，对多阶段数据流水线、代码迁移、构建管道等场景具有立竿见影的效率提升效果。

useAgent ⭐ 282

开源 AI 协作平台，让 AI 智能体独立完成工作

BunTypeScriptPostgres + pgvectorDaytona / CubeSandboxnoVNCSlack APIGitHub AppTerraform
useAgent 是一个开源的 AI 协作平台，将 Claude Code、Codex、OpenCode 等 AI 智能体转变为团队中的真正「同事」。它为每个智能体分配独立的云端 Linux 沙箱环境，配备终端、浏览器、可视桌面（noVNC）和录屏功能，让智能体能够自主完成完整的工作交付物——网站、演示文稿、电子表格、研究报告和经过测试的 PR，而不只是给出建议。核心架构基于事件溯源（event sourcing）设计，所有会话记录存储在 Postgres 中，确保运行过程可追溯、可恢复，即使后端重启也能无缝恢复工作状态。平台采用「可信网关」模式，所有凭证和敏感信息不进入沙箱，集成工具（GitHub、Slack、Gmail、Linear 等）通过类型化工具接口调用。支持从 GitHub 导入技能文件（SKILL.md）、构建组织级知识库、人机协作审批流程，以及原生文档格式（DOCX、XLSX、PPTX）的生成与编辑。技术栈使用 Bun 运行时、Postgres + pgvector 扩展、Daytona 或 CubeSandbox 作为沙箱后端，完全支持自托管部署在任意云服务商或物理服务器上。项目遵循 AGPL-3.0 协议，目前处于 Alpha 阶段但已在实际生产环境运行。
useAgent 突破了当前 AI 助手「只提建议」的限制，通过沙箱隔离 + 事件溯源 + 可信网关三层架构，实现了 AI 智能体真正意义上的自主工作交付。引擎无关的设计让团队不被单一 AI 提供商锁定，持久化会话保证了企业级可靠性，完全开源且支持自托管满足数据合规需求。对于希望将 AI 深度集成到工作流的团队，这是一个生产级可用的基础设施方案。

Headcount 是一个为 Claude Code 设计的模块化 Agent 组织架构，将 AI 能力结构化为一家完整的虚拟公司：1 位 CEO 统领 16 个部门，涵盖 172 项专业技能。每个部门都是独立可安装的插件，项目可按需加载所需功能而非全量引入。技能采用 `department:skill` 命名空间设计（如 `security:threat-modeling`、`finance:unit-economics`），避免命名冲突。当用户提出请求时，系统自动匹配并激活对应专家（如询问落地页转化问题时加载 `demand-generation:landing-page-cro-expert`），也可通过 `/finance:financial-modeling` 直接调用特定技能。核心部门包括 CEO 办公室（战略决策、融资、增长咨询）、技术部（架构设计、CI/CD、系统调试）、安全部（威胁建模、合规审计）、财务部（财务建模、单位经济学）、法务部（合同审查、隐私合规）、人力资源（招聘、绩效管理）、市场/销售/客户成功等完整业务条线。部分部门为 reviewer-class 类型，会在风险决策前主动介入审查而非被动给建议。每个部门同时提供 `.claude/agents/` 下的 Agent Charter，支持作为独立子代理委派任务并拥有专属写入权限。
